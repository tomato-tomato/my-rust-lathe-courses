# 续写教程

为已存储的教程添加下一部分。新部分必须延续*该*教程——它的示例、它的数字、它的 voice、它的风格标杆侧重——而不是一篇全新的泛化教程。

关于结构、标注和风格标杆的所有内容来自 `<SKILL_DIR>/SKILL.md` 的不变量、教程结构和风格标杆节；研究纪律和写法细节来自 `<SKILL_DIR>/references/generate.md`。

**触发格式：**

- 常规续写：`/lathe 续写|extend <slug> [指导]`
- 收尾完结：`/lathe 续写 收尾 <slug>`——"续写"关键词后紧跟"收尾、完结、总结"（finish、wrap up）时进入**收尾模式**（见文末专节），不执行下方常规协议。

## 协议

0. **解析教程位置。** 按 `<SKILL_DIR>/SKILL.md`"教程位置解析规则"找到该 slug 的实际目录。**若目录中有 `part-*.md` 但 `metadata.json` 缺失或损坏**，先执行 `<SKILL_DIR>/SKILL.md`"metadata.json 自愈"，重建确认后再继续。

1. **吸收现有教程。** 阅读该教程目录中的每个部分（`part-NN.md`）和 `metadata.json`。在写下一个字之前你需要关键的上下文：
   - **控制性示例**和**固定数字**（采样率、页面大小、缓冲区大小）——精确复用它们。
   - **控制性隐喻**（如有），以及之前的部分是否已告别它。
   - **voice**。从 `metadata.json` 读取 `voice` 字段并应用对应的 voice 规范（内置 voice 的完整规范见 `<SKILL_DIR>/references/voice.md` "内置 voice"一节；自定义 voice 读取 `<TUTORIALS_DIR>/voices/<名称>.md`）。不要重新选择或漂移 voice；结构和内容仍遵循 `<SKILL_DIR>/SKILL.md` 的教程结构，它在与 voice 冲突时获胜。
   - **语言**。从 `metadata.json` 读取 `language` 字段，新部分保持同一语言（见 `<SKILL_DIR>/SKILL.md`"教程语言"）；字段缺失时按已有部分推断并在本次更新 metadata 时补上。
   - **风格标杆侧重**。延续之前部分的风格标杆主锚点（见 `<SKILL_DIR>/references/style-benchmarks.md` 场景侧重表）——如果 part-01 按 Nystrom 式散文节奏写，新部分保持相同的写作节奏和结构选择，不要切换到其他风格标杆。
   - **读者的水平**。新引入的重要概念遵循 generate.md"概念锚定"原则：从读者已有知识引申，锚点与其水平匹配。
   - **学习目标与达成度**。从 `metadata.json` 读取 `goal` 字段；字段缺失（旧教程）时，从 `topic` 与已有内容推断一个学习目标，并在步骤 6 更新 metadata 时补上。随后对照 `goal` 逐项评估已有部分的覆盖情况，得出 **已达成 / 基本达成 / 未达成** 的结论及依据——该评估在步骤 5 写入新部分，不单独询问、不打断流程。
   - **仓库和锁定的工具版本**在 `metadata.json` 中（`repo`、`repo_branch`、`tools`）——新部分*继承*它们。基于相同版本写作；不要静默升级到更新的工具链。（如果读者明确想迁移到新版本，这是一个信号——可能是时候创建一个新教程了。）
   - 上一部分 **"接下来"** 指向的方向——除非用户的指导重新定向，否则这就是你的任务。

2. **询问本地项目路径（可选）。** 向用户展示以下提示：

   ```
   你是否有已完成的本地项目代码？如果有，提供项目路径可以让我基于你当前的实际代码来续写下一部分课程。

   1. ✅ **提供项目路径** — 我会读取项目代码，基于当前进度续写
   2. ⏭️ **跳过** — 基于教程中描述的状态续写

   请回复编号，或直接输入项目路径。
   ```

   - **如果用户提供了路径：** 读取项目的关键文件（源代码、配置文件、目录结构等），了解当前实际进度。将路径记录到 `metadata.json` 的 `local_project_path` 字段。
   - **如果用户选择跳过：** 基于教程已有部分中描述的代码状态续写，不读取本地文件。

3. **先研究。** 与 generate.md"先研究"步骤同样的纪律：实际打开 3-8 个该新部分引入内容的权威来源，在关键事实旁记录 URL，并对每个关键声明有据可依或用 `[!UNVERIFIED]` 标记。新引入的示例代码同样遵循 generate.md 预检中的**版本-特性一致性**检查：特性必须在继承的锁定版本下成立，不确定时查官方 changelog。

4. **确定下一部分编号。** 从 `metadata.json` 读取现有的 `parts` 数组。新部分是 `part-NN.md`，其中 NN 是下一个序号，零填充到 2 位（例如，如果 `parts` 有 `["part-01.md"]`，下一个是 `part-02.md`；若已有 `part-02-review.md` 复习材料，下一个常规部分是 `part-03.md`）。**检查该名称的部分是否已存在。** 如果存在，告诉用户并停止。

5. **写入该部分**到该教程目录下的 `<part-NN.md>`。
   - 遵循 SKILL.md"教程结构"（单一事实源）——引子、`## 你将构建什么`、前置条件、具体章节标题、`## 检查点`、`## 接下来`、`## 练习`、`## 来源`；写法细节参考 generate.md。每个部分独立成篇并以检查点结尾。
   - 因为这是**第 N ≥ 2 部分**，以 `> [!RECALL]` 间隔检索节拍开头：一个关于之前部分关键概念的问题。
   - **目标达成回顾**：在 `## 接下来` 之前插入 `## 目标达成回顾` 小节——陈述原定学习目标（`goal` 字段）、列出已覆盖的内容与尚未覆盖的部分（如有）、给出步骤 1 的达成结论。客观克制，不催促收尾；末尾一句话提示选项：继续延伸新方向，或执行 `/lathe 续写 收尾 <slug>` 完结课程。由用户自行判断。
   - **一个文件，仅此部分。** 不要写 `index.md`，不要碰之前的部分，不要写多个部分。

6. **更新 `metadata.json`。** 读取现有文件，然后更新：
   - 将新部分文件名追加到 `parts` 数组。
   - 将新查阅的来源 URL 追加到 `sources` 数组（去重）。
   - `goal` 字段缺失的旧教程，补上步骤 1 推断的学习目标。
   - 如果用户提供了本地项目路径，更新 `local_project_path` 字段。
   - 将 `model` 字段更新为*你*运行的模型（如 `QoderWork`）。
   - 将 `status` 设为 `unverified`（见 `<SKILL_DIR>/SKILL.md`"status 状态机"）——若原状态为 `completed`，此写入即撤销完结，课程重新开放。
   - 顶部缺少 `_warning` 字段的旧教程，写回时补上（见 `<SKILL_DIR>/SKILL.md`"metadata.json 结构"）。
   - 写回更新后的文件。若 `~/.lathe/config.json` 的 `tutorial_paths` 中尚未登记该教程，一并登记其位置。

7. **告诉用户**已添加——如何查看（直接在 QoderWork 中打开 markdown 文件），验证是可选的；若原状态为 `completed`，一并告知课程已重新开放。然后保持会话以回答后续问题。

## 收尾模式（`/lathe 续写 收尾 <slug>`）

当续写指令中含"收尾/完结/总结"意图时执行本模式——生成总结部分并完结课程，不引入新教学内容。

1. **吸收教程**：同常规协议步骤 0 和步骤 1（路径解析、阅读全部部分与 metadata、目标达成评估）。跳过本地项目路径询问；收尾不做新的网络研究（除非总结需要核实某个关键事实）。
2. **确定部分编号**：同常规步骤 4 的规则（含复习部分在内的最大编号 + 1）。
3. **写入总结部分** `part-NN.md`，内容要求：
   - **全课程回顾**：逐部分一句话总结构建了什么、学到了什么；
   - **知识图谱**：用 Mermaid `flowchart` 或表格整理课程核心概念及其关系；
   - **目标对照**：对应 `goal` 字段逐项说明已建立的能力；未覆盖的部分如实说明；
   - **练习方向**：3-5 个可基于本课程自主探索的方向，每个具体到可立即开始；
   - **寄语**：遵循 SKILL.md"教程结构"中收尾寄语的写法（邀请读者走出铺设的道路）。
   - 末尾说明课程已完结；未来想继续精进时直接续写即可，课程会自动重新开放。
   - 总结部分**不写** `## 检查点`（无可执行新内容），用一段"回顾自检"代替：列出 3-5 个贯穿全课程的关键问题供读者自测。
4. **更新 metadata**：新部分加入 `parts`；`status` 设为 `completed`；更新 `model`；`goal` 缺失时补上。
5. **告诉用户**课程已完结——总结部分的路径、`status` 已标记 `completed`；随时可用 `/lathe 续写 <slug>` 重新开放，或用 `/lathe 验证 <slug>` 确认最终可用性。

## 边界

- 写入新的 `part-NN.md`（常规或总结）和更新 `metadata.json` 是唯一的文件写入操作。
- 不要验证，不要写 `index.md`，不要写多个部分，不要编辑现有部分。
- 常规续写不得在未经收尾模式的情况下自行将 `status` 置为 `completed`。
